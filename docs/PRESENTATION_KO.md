# REvFLY 발표·시연 안내

## 4분 발표 흐름

**문제 · 40초**

“초파리 시뮬레이터는 근육 입력이 주어졌을 때 다리가 어떻게 움직이는지 계산합니다. 저는 그 관계를 거꾸로 써서, 원하는 관절 움직임을 주면 어떤 운동 발화율이 필요한지 찾는 엔진을 만들었습니다.”

**엔진 · 50초**

왼쪽 앞다리의 7축 목표 각도를 420 ms 동안 입력합니다. MLP가 15개 운동 채널의 발화율을 예측하면, 이를 근육 구동으로 변환해 FlyMimic/MuJoCo에서 재생합니다. 목표와 재생의 차이를 재고 필요하면 해당 목표의 발화율만 보정합니다. 엔진에서 계산하고, 화면에서 궤적과 탑뷰 영상을 확인합니다.

**검증 · 75초**

학습·모델 선택에 없던 합성 움직임 3계열에서 9개 목표를 만들었습니다. 각각 실제로 같은 물리 모델에서 만들 수 있는 궤적입니다. 목표와 무관한 발화율에서 출발하는 방법과 MLP가 예측한 발화율에서 출발하는 방법에 동일한 순방향 탐색과 30초를 적용했습니다. 평균 오차는 **10.412° → 6.056°**, 실패율은 **9/9 → 3/9**였습니다. 실패는 7축 전체의 RMSE가 0.1 rad(5.7296°)를 넘는 경우입니다. [비교 그래프와 수치](../reports/unseen_motion_families_v2/README.md)

**한계와 의미 · 45초**

같은 목표를 기울기 기반으로 비교했을 때는 18회 중 15회가 기울기 검사에서 멈췄고, 양쪽 모두 기준을 통과하지 못했습니다. 위 성능은 그래서 별도로 시행한 순방향 보정 결과입니다. 실험 범위는 몸통을 고정한 시뮬레이션 속 앞다리 7축입니다. 엔진이 제공하는 것은 목표 궤적을 비교 가능한 운동 명령으로 바꾸고, 같은 시뮬레이터에서 오차를 확인하는 절차입니다.

## 시연

발표 전에 [설치 절차](../README.md#설치)를 마친 환경에서 다음 두 명령을 준비합니다.

```bash
sensory-engine-v2 run-multijoint --goal-family swing_scaled --scale 0.92 \
  --mode fast --output ./presentation-swing --render
sensory-engine-v2 serve --host 127.0.0.1 --port 8505 --ui \
  --model-id 20261115_v2_fastbridge_lowenergy
```

[Control Studio](http://127.0.0.1:8505/)에서 왼쪽 앞다리 7축 모드와 스윙 목표를 열고, 목표 곡선과 재생 곡선을 한 축씩 비교합니다. 15개 근육 중 하나의 발화율과 탑뷰 영상을 보여줍니다. 이 스윙은 실행 시연이고, 9개 미사용 목표의 점수는 별도 실험에서 얻었습니다. 실시간 렌더링이 어려우면 `presentation-swing`에 미리 생성된 영상을 재생합니다.

## 예상 질문

| 질문 | 답변 |
| --- | --- |
| GNN으로 움직임을 만든 건가요? | 감각에서 운동뉴런 반응을 예측할 때 GNN을 실험했습니다. 발표하는 REvFLY 역제어 경로는 ResidualNorm MLP와 MuJoCo를 사용합니다. |
| 6.056°는 어떤 오차인가요? | 목표와 재생의 7개 축을 420 ms 동안 비교한 RMSE를 목표 9개에서 평균한 값입니다. 관절별 순간 오차는 더 클 수 있습니다. |
| 그 발화율이 정답인가요? | 같은 움직임을 만드는 가능한 명령 중 하나입니다. 선택한 명령을 물리에서 다시 재생하고 그 오차를 기록했습니다. |
| 실제 초파리를 움직였나요? | 연구 결과는 FlyMimic 시뮬레이션에서 얻었습니다. 실물에 적용하려면 발화율을 유도할 자극과 실제 움직임을 별도 검증해야 합니다. |
| FlyMimic과 새로 만든 부분은 어떻게 연결되나요? | FlyMimic이 제공하는 근골격 모델로 움직임을 재생했습니다. 새 엔진은 그 위에 목표 궤적에서 역으로 발화율을 만드는 모델, 보정과 검증, Python API와 로컬 실험 화면을 연결했습니다. |
